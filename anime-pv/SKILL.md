# 二次元 PV 制作

以成片质量为先，用视觉和动态证据确认方向，留下可重新渲染的工程。模型负责制作判断和送审前自检，用户确认方向与接受范围；不预设画风、镜头语法或唯一渲染引擎。

## 进入项目

- 已有项目：先读根目录 `HANDOFF.md`，按链接恢复当前版本、批准项和下一步。不要整包加载历史。按 [交接规范](references/handoff.md) 做恢复检查。
- 新项目：区分复刻或自主创作，只追问显著影响结果且无法推断的问题。可用 `uv run <skill>/scripts/project.py init <项目目录> --mode replica|original` 建立入口。
- `<skill>` 指本文件所在目录，命令中的占位路径须替换。Python 一律用 uv。项目生成在独立目录，不写入 skill 资源目录。

## 始终保持

1. 完全不用视频生成模型，包括插帧。本地 AI 工具默认不运行；抠像/分割、修补、超分、OCR 等非生成用途能明显提升质量时，向用户提出具体方案（用途、模型与许可、下载体积、存放位置），获同意后安装运行并记入交接。连续角色表演、转头等难点先做可行性片段；无法达标要展示差距，不能静默降级。
2. 质量优先：效果有差距时选效果更好的路线，即使更复杂；效果相当时再选简单、方便、节省 token 的工具。不设费用或 token 预算。依据用户要求和质量参考主动打磨，首次样片也需自检；用户批准方向不免除后续制作缺陷检查。
3. 有视觉或运动分歧时提供生图、HTML 动画或视频片段等可复核的 demo，运动问题用动态样片验证。证据如实：只把实际执行、实际覆盖的检查记为通过——抽帧不等于连续观看，预演不等于终版画质，模型自检不等于用户批准，其他机器或旧版本的结论不自动继承；未验证项留在交接中。
4. 首次需要生图前，请用户明确授权生图途径：agent 可用的生图工具（内置或 MCP 提供）和/或后端 API profile，可一次授权多个。授权范围内按素材择优并记录每张采用素材的途径；已有授权无需重复询问，授权外的途径或后端须先获同意。没有生图需求时无需授权。API 路线读取 [生图后端](references/image-backends.md)。
5. 阶段内自主推进。阶段成果完成后展示证据、更新交接并停在边界，按 [交接规范](references/handoff.md) 给出可复制的续接提示词；修改在当前窗口处理。用户在新窗口发送续接提示词即确认所列成果并授权下一阶段：记录批准后直接开展下一阶段，不再等待同一批准。用户明确要求时可合并、跳过阶段或在当前窗口继续，记录覆盖范围。
6. 本任务可控制的生成文件默认全部放在 PV 项目目录内，包括临时脚本、下载、抽帧、日志、缓存和中间渲染；临时内容用 `<项目>/tmp/`，缓存用 `<项目>/.cache/`，不要主动写入 `/tmp`、`/private/tmp` 或其他项目外临时目录。执行工具前按 [工程文件位置约定](references/production.md#文件位置与临时目录) 设置工作目录、输出路径及进程级临时/缓存位置；工具强制外部输出时记录例外并将所需结果归档到项目内。

## 两种模式

### 角色替换复刻

以原片最终可见画面 1∶1 还原为目标，仅替换指定角色。新角色身份特征优先保留；与原轮廓、遮挡、构图的冲突做最小改动，并提前展示、确认。时间轴、镜头运动、排版和转场严格对齐。角色姓名等关联文字集中确认，其余文字和元素保留。

没有分层素材时可提取、重绘、补全、重新合成；未知区域以视觉连续性为标准，不要求复原原作者的制作过程。素材不足可补齐，但先批准角色视觉基准，并区分用户素材与新增设计。

原音轨直接 stream copy，不重新编码，不自行裁切或改编。先检查全部音轨及时间戳；封装不兼容时优先换封装，仍冲突再请用户选择。原片无音轨则保持无音轨。

### 自主创作

可从参考片提炼风格，用 demo 确认借鉴项，默认重新组织镜头；逐镜头照搬应归入复刻。用户提供音频时先确认使用区间和成片时长，裁切、循环、淡变、添加音效均作为方案批准。没有用户音频就交付真正无音轨的视频，不附静音轨、不自行找音乐。

## 默认四阶段

| 阶段 | 达成共识所需的证据 |
| --- | --- |
| 1 项目确认与预检 | 模式、输入、输出规格、音频政策、角色与关联文字范围（提问确认）；质量目标与参考、环境检查、技术路线与高风险镜头（记录后随阶段 2 样片一并确认） |
| 2 视觉与动态定案 | 镜头设计记录、角色基准、代表构图、排版与运动 demo；以最终渲染链路验证代表性与难点片段；批准具体文件版本与允许差异 |
| 3 全片预演 | 可播放、覆盖完整时间与所有镜头；角色、构图、主要文字、关键运动具有代表性；检查全片节奏和镜头接续，明确暂缺项 |
| 4 正式制作与验收 | 正式成片、工程核查、连续动态与视觉对照、用户验收、足以重渲染的工程与依赖说明 |

阶段 1 不单独停顿：问清只能由用户决定的事项后直接进入阶段 2，用样片而非文字方案确认方向。默认在阶段 2、3 完成后停在边界，阶段 4 以用户验收结束。

制定质量目标时读取 [制作质量与审片](references/quality.md)，后续按当前阶段使用其中的镜头、素材和送审要求。选技术路线、设计镜头和自检时参考 [制作手法与工具](references/craft.md)，其中均为可选手段。预演可降低分辨率、暂缓昂贵细节，但不能用占位图掩盖关键未决问题。

每阶段遵循 [交接规范](references/handoff.md)。回改保留旧版本，只撤销受影响批准项，不重置整个项目。

## 工程与交付

第一阶段及正式制作前读取 [工程与验收](references/production.md)。先运行只读预检，再为当前技术路线补充字体、编码器、渲染依赖验证；缺失工具提供当前系统的安装方法。

`scripts/project.py` 提供初始化、预检（含 ffmpeg 编码器与滤镜、中日文字体及可选渲染引擎）、媒体信息与按文件清单打包。`scripts/media.py` 生成胶片条、与原片同时间点对照、切点检测，以及工程与音轨逐包核验，作为自检证据。`scripts/image_backend.py` 负责四类生图协议、按 `--profile` 选择配置、异步任务恢复与结果落盘；不替模型决定画面。

交付视频，以及素材、工程/脚本、依赖记录、运行命令和验收记录；不强制 GUI 可编辑。必要素材不得当缓存删除。交接、日志、版本库和交付包不含凭证。
