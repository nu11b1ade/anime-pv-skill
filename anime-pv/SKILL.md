# 二次元 PV 制作

以用户批准的视觉和动态证据为制作依据，留下可重新渲染的工程。约束工程与交接，不预设画风、镜头语法或唯一渲染引擎。

## 进入项目

- 已有项目：先读根目录 `HANDOFF.md`，按链接恢复当前版本、批准项和下一步。不要整包加载历史。按 [交接规范](references/handoff.md) 做恢复检查。
- 新项目：区分复刻或自主创作，只追问显著影响结果且无法推断的问题。可用 `uv run <skill>/scripts/project.py init <项目目录> --mode replica|original` 建立入口。
- `<skill>` 指本文件所在目录，命令中的占位路径须替换。Python 一律用 uv。项目生成在独立目录，不写入 skill 资源目录。

## 始终保持

1. 完全不用视频生成模型。默认不运行任何本地 AI 模型。连续角色表演、转头等难点先做可行性片段；无法达标要展示差距，不能静默降级。
2. 同等质量下选择简单、方便、节省 token 的工具，不设费用或 token 预算。质量底线由批准样片和明确要求决定。
3. 有视觉或运动分歧时提供生图、HTML 动画或视频片段等 demo。静帧不能代替动态验证。样片是可复核文件，而非只有文字承诺。
4. 首次需要生图前，由用户明确选择 **agent 内置生图** 或 **后端 API**，记录并沿用；已有授权无需重复询问，切换途径或后端须有明确同意。没有生图需求时无需选择。API 路线读取 [生图后端](references/image-backends.md)。
5. 阶段内自主推进。成果制作到可审阅后才请求批准；沉默不是批准。批准后更新交接，默认停在边界，由用户新开窗口继续。用户明确要求时可合并、跳过阶段或在当前窗口继续，记录覆盖范围。

## 两种模式

### 角色替换复刻

以原片最终可见画面 1∶1 还原为目标，仅替换指定角色。新角色身份特征优先保留；与原轮廓、遮挡、构图的冲突做最小改动，并提前展示、确认。时间轴、镜头运动、排版和转场严格对齐。角色姓名等关联文字集中确认，其余文字和元素保留。

没有分层素材时可提取、重绘、补全、重新合成；未知区域以视觉连续性为标准，不要求复原原作者的制作过程。素材不足可补齐，但先批准角色视觉基准，并区分用户素材与新增设计。

原音轨直接 stream copy，不重新编码，不自行裁切或改编。先检查全部音轨及时间戳；封装不兼容时优先换封装，仍冲突再请用户选择。原片无音轨则保持无音轨。

### 自主创作

可从参考片提炼风格，用 demo 确认借鉴项，默认重新组织镜头；逐镜头照搬应归入复刻。用户提供音频时先确认使用区间和成片时长，裁切、循环、淡变、添加音效均作为方案批准。没有用户音频就交付真正无音轨的视频，不附静音轨、不自行找音乐。

## 默认四阶段

| 阶段 | 达成共识所需的证据 |
| --- | --- |
| 1 项目确认与预检 | 模式、输入、输出规格、音频政策、角色与关联文字范围；参考片分析、环境检查、技术路线与未验证风险 |
| 2 视觉与动态定案 | 角色基准、代表构图、排版与运动 demo；复刻优先验证还原难点，创作优先确认方向；批准具体文件版本与允许差异 |
| 3 全片预演 | 可播放、覆盖完整时间与所有镜头；角色、构图、主要文字、关键运动具有代表性；明确暂缺项，不用占位图掩盖关键未决问题 |
| 4 正式制作与验收 | 正式成片、工程核查、连续动态与视觉对照、用户验收、足以重渲染的工程与依赖说明 |

预演可降低分辨率、暂缓昂贵细节，但必须能代表最终方向。每阶段遵循 [交接规范](references/handoff.md)。回改保留旧版本，只撤销受影响批准项，不重置整个项目。

## 工程与交付

第一阶段及正式制作前读取 [工程与验收](references/production.md)。先运行只读预检，再为当前技术路线补充字体、编码器、渲染依赖验证；缺失工具提供当前系统的安装方法。

`scripts/project.py` 提供初始化、预检、媒体信息与按文件清单打包。`scripts/image_backend.py` 负责五类生图协议、配置查找、异步任务恢复与结果落盘；不替模型决定画面。

交付视频，以及素材、工程/脚本、依赖记录、运行命令和验收记录；不强制 GUI 可编辑。必要素材不得当缓存删除。交接、日志、版本库和交付包不含凭证。

维护脚本时用 `uv run --with httpx --with python-dotenv --with pillow -m unittest discover -s <skill>/scripts/tests -v` 运行离线测试。测试通过不等于真实平台或所有操作系统均已验证。
