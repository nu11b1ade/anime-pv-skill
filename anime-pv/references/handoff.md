# 项目状态与阶段交接

项目目录承载完整状态，`HANDOFF.md` 是唯一恢复入口。入口保持短小；链接使用项目内相对路径，方便迁移。推荐按用途放置 inputs、assets、design、previews、render、deliverables、state，不强迫特定工程内部布局。

## 写入与批准

每个批准项至少包含：稳定 ID、决定内容、状态（proposed / approved / invalidated）、用户确认的时间或消息摘要、适用范围、所依赖的决定 ID，以及证据文件版本/哈希。模型验证通过不等于用户批准。更新入口前保存旧版到 `state/history/`；素材、demo、工程使用不同版本名，不覆盖已批准证据。

使用 [HANDOFF 模板](../assets/HANDOFF.template.md) 建立入口。完成阶段后：

1. 给用户展示可审阅成果、关键差异和未验证项。
2. 保存决定和证据版本，更新入口中当前阶段、下一阶段、验证状态及下一步。尚未收到批准时如实记录“成果已完成，待用户发送续接提示词确认”，不得仅因生成提示词就标记 approved。
3. 默认停下，按下方格式给出新窗口指导和完整续接提示词。用户需修改当前阶段时在当前窗口提出；满意后直接新开窗口发送提示词，即确认列明的本阶段成果并授权下一阶段，不要求先在旧窗口额外回复批准。
4. 收到用户发送的续接提示词后，新窗口记录真实批准范围和本次消息依据，直接开展下一阶段，不要再次等待同一项批准，也不要只记录批准便再次交接停止。用户已明确要求当前窗口继续时照做，无需要求换窗口。

中途暂停也更新入口，但保持阶段未批准。不得为产生交接而伪造共识。

## 停止时的用户回复

阶段成果完成并停止时，先简述成果、版本及未验证项，提供 `HANDOFF.md` 链接，再写明：“如需修改，请直接在当前对话提出；确认本阶段成果后，新建一个可访问项目目录的对话，复制发送下面整段提示词，即可直接开始下一阶段。”不要同时要求用户先回复批准。提示词必须单独放入一个可复制的 `text` 代码块，不要只保存在文件中。发送前将下列占位内容替换成实际值，不让用户手动拼接路径、版本或阶段；项目内交接文件仍使用相对路径，只有发给用户的提示词使用当前机器的绝对路径。

续接提示词只承载入口、本次确认和目标阶段，通常三句即可。技能已有的规则、交接已记录的决定和下一阶段任务细节均不重复写入：例如角色/服装、生图选择、音轨政策、验证要求、临时目录、批准记录流程和阶段结束流程。这些信息缺失时先补入交接文件，不靠加长提示词补救。唯一保留的成果版本引用用于界定本次批准范围，不展开复述成果内容；交接中有版本化成果清单时可直接引用该清单。

```text
请使用 anime-pv 技能，读取 <项目实际绝对路径>/HANDOFF.md。
我确认阶段 <已完成阶段编号> 的成果 <成果或成果清单的相对路径及版本>。
请直接开始阶段 <下一阶段编号与名称>。
```

阶段 4 验收完毕时明确说明制作已完成，无需再开窗口；此时提示词用于后续修改或重渲染，不得虚构“下一阶段”。中途暂停、成果未完成时，提示词只保留技能与交接入口及“继续阶段 N 的未完成任务”，实际状态和剩余任务写入交接，不套用成果确认句或虚构阶段完成。仅打开新窗口、读取文件或要求修改不算批准；用户发送阶段续接提示词才是确认动作。

## 新窗口恢复检查

先读入口，再只读当前任务相关资料。核对模式、输出规格、音频政策、当前版本、已批准证据存在且哈希未变、生图途径/后端已获选择、运行命令与依赖是否可用。恢复当前质量目标、相关镜头及未决缺陷，不把旧项目未记录的检查当成通过。配置来源只记录位置、协议、模型等非敏感信息，不记录 key 或带签名参数的 URL。

用户当前续接消息对指定成果的确认是新的批准依据，优先于旧入口的“待批准”状态：保存旧版、记录批准、更新下一步，然后在本次任务中直接执行下一阶段。确认只覆盖提示词所列成果版本；文件缺失、版本变化或仍缺生图途径等独立选择时，仅处理受影响事项，不重新询问已确认的阶段整体批准。

简短说明恢复到哪一步、哪些项目仍待验证，然后继续授权范围内的工作。缺文件或证据变更只阻止依赖它的任务；不要重新设计未受影响的批准内容。换机器后工具和字体需要重检，源机器“通过”不自动继承。

## 回改

先说明变更影响的素材、镜头和批准 ID。保留原版本，只将直接及传递依赖项标为 invalidated；无关项保持 approved。新证据完成后只重新确认必要部分，并更新当前版本指针。

## 搬迁与打包

创建 `state/package-files.txt`，逐行列出重渲染所需的项目内文件：入口、决定、批准样片、输入、素材、字体（可分发时）、渲染代码、锁文件和运行说明等。运行：

```sh
uv run <skill>/scripts/project.py pack <项目> --manifest state/package-files.txt --output <项目>/deliverables/pv-project.zip
```

脚本只复制明确列出的文件，拒绝越界、符号链接和常见凭证文件名；模型仍需检查清单内容，不能把文件名检查当作完整的秘密扫描。不打包 .env、任务缓存、环境目录和不必要的渲染缓存。目标机解压后从入口恢复，不依赖旧机器绝对路径。
