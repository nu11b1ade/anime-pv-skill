# 制作手法与工具

选技术路线、设计镜头和自检时参考。以下是可选手段，按镜头意图、参考和环境取用，不是必选项或风格规定；用得准比堆得多更重要。有利于质量的其他工具和方法同样可用，本地 AI 与生图途径仍按 SKILL.md 的授权规则。

## 渲染路线

| 路线 | 擅长 | 注意 |
| --- | --- | --- |
| 程序化合成（Python：NumPy、Pillow、OpenCV、skia-python 等 → 帧序列 → ffmpeg 编码） | 完全可控；浮点与预乘 alpha 合成；运动模糊、景深、光效和逐帧检查都能自己实现 | 时间轴与缓动需自建；大画幅注意内存和渲染时间 |
| 浏览器渲染（HTML/CSS/SVG/Canvas/WebGL；Remotion、Motion Canvas，或 Playwright 逐帧截图） | 排版、竖排、字距、描边、矢量动态图形、滤镜 | 页面提供按帧号渲染的接口，逐帧截取，不依赖实时录屏；字体本地加载；各框架许可条款不同 |
| Blender（bpy 无头渲染） | 多层视差、2.5D 摄影机、真实景深、合成节点、Grease Pencil | 需安装且体积大；记录版本 |
| ffmpeg 滤镜链 | 拼接、转场（xfade）、封装编码、快速预演 | zoompan 等按整数像素取样，慢推慢摇会抖；平滑镜头运动应在上游以子像素精度渲染 |
| 用户已有的专业软件（After Effects aerender/ExtendScript、DaVinci Resolve/Fusion 脚本等） | 成熟的合成与特效生态 | 需要用户已安装并授权；记录版本；单独核对能否重渲染 |

路线可以混用，例如 Python 合成角色与背景层、浏览器渲染文字层、ffmpeg 负责封装。定案效果在最终链路复核。

## 二次元观感的常用抓手

- **作画节奏**：角色作画常用一拍二、一拍三（每秒 12 或 8 张），摄影机运动和特效逐帧推进。有限动画是风格，不是降级。插帧会破坏这种质感并产生形变，不使用。
- **撮影处理**：扩散/光晕、透過光、パラ（渐变叠色）、层间景深模糊、镜头光斑、色差、颗粒、暗角、画面震动、速度线/集中线、闪白/黑场、分屏。依镜头意图选用，统一光源方向与色调。
- **运动**：缓入缓出、预备与过冲、跟随与重叠（发梢、衣摆、飘带）。快速运动加运动模糊，做法是在快门区间内渲染多个子帧后取平均。切在动作上，用遮挡、闪帧和镜头运动衔接。
- **文字演出**：标题、角色名牌、宣传语和日期卡都是 PV 的主画面元素。需要精确字形时用文字或矢量层。检查中文、日文字形覆盖，描边和投影在压缩后是否可读，并按字数留足阅读时间。
- **音乐节奏**：有用户音频时按拍点和段落规划切镜与文字。没有音频时可以按设定的 BPM 网格设计，方便日后配乐；仍不自行添加音乐。

## 难点镜头的二维方案

- **角色表演**：关键姿势逐张生成，配合有限动画节奏，每张都以批准的角色基准为参考；帧间一致性优先于单帧精细度。也可以把角色分层（头发、眼、口、身体、配件），用网格/木偶变形做呼吸、眨眼、口型、发梢摆动。大幅表演可以用剪影、遮挡、smear 帧或镜头运动来化解。
- **复刻中去除原角色**：摇移、推拉镜头可以把多帧配准拼接成完整背景板，用其他帧露出的背景填补被角色遮挡的区域（时间中值等经典方法），剩下的缺口再修补。本地分割、修补、超分模型按 SKILL.md 的本地 AI 规则提议使用。
- **镜头运动匹配**：用特征点匹配或光流（OpenCV）估计原镜头的平移、缩放、旋转曲线，让新角色层与原背景严格同步。

## 画质技术要点

- **渲染精度**：以高于交付的内部分辨率或子像素变换渲染，再高质量缩小；避免每帧整数取整造成抖动与锯齿。
- **合成**：用预乘 alpha；光效与模糊在线性光中混合更自然；在实际背景上检查抠像边缘和光晕的亮边或暗边。
- **色彩**：渐变和暗部防色带，可用高位深中间格式、抖动或细颗粒。RGB 转 YUV 时明确 BT.709 矩阵和色彩范围（如 ffmpeg `scale=out_color_matrix=bt709:out_range=tv`），并写入 `-colorspace`/`-color_primaries`/`-color_trc` 标记，避免不同播放器偏色。
- **编码与交付**：需要时同时交付母版（ProRes 4444/422 HQ 或无损 FFV1）和分发版（H.264/H.265，yuv420p；动画内容可用 x264 `-tune animation`，CRF 约 14–18）。送审预览用 H.264 MP4 加 `-movflags +faststart`，用户可以直接播放。
- **生图素材**：比交付画面多留出运动与裁切余量。分辨率不够时，优先以更高分辨率生成或分区生成。角色素材优先透明或易抠的纯色背景。多参考时写明每张图的用途；所选模型支持身份/输入保真类参数时（例如部分 OpenAI 图像模型编辑接口的 `input_fidelity`），按官方文档使用。探索阶段可以并行多个 job 比较变体。

## 动态自检手段

模型通常只能看静帧，用下列证据弥补，覆盖范围仍按 [制作质量与审片](quality.md) 如实记录：

- **高密度胶片条**：逐帧或每 2 帧一张，检查缓动、跳变、闪烁和一拍二节奏：`media.py sheet --every-frame`。
- **同时间点对照**：复刻时与原片并排或差分，差分只用于定位：`media.py compare --diff`。
- **切点**：与原片的切点对齐到 ±1 帧，或测量参考片的镜头时长：`media.py cuts`。
- **工程核查**：可解码性、帧时间、黑帧/冻结帧、色彩标记、音轨逐包一致：`media.py verify`。
- **独立审阅**：agent 支持子代理或新上下文时，让未参与制作的审阅者只看质量目标、参考和证据来评审，减少自评偏差。
- **外部视频模型**：能理解视频的模型可以作辅助审阅，但会把成片发送到外部服务，须用户同意；它不替代用户验收。

命令用法见 `uv run <skill>/scripts/media.py <子命令> --help`；输出是审片证据，不是质量分数。
