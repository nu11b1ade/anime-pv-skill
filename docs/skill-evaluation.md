# 完整 PV 与工作流评测

这是维护评测方案，当前尚无完成记录。离线测试、文档走查和渲染器冒烟测试都不能据此写成“完整 PV 质量已验证”。实际制作从 anime-pv/SKILL.md 进入，使用独立项目目录并沿用真实用户选择与批准，不伪造阶段确认。

## 代表性用例

| 用例 | 准备与目标 | 重点观察 |
| --- | --- | --- |
| 短片角色替换复刻 | 准备约 8–12 秒、可公开使用的参考片和新角色素材；包含多个镜头、遮挡及转场。保留参考工程便于核查。按原片音轨政策制作 | 新角色身份、时间对应、未替换区域、运动与转场连续性，以及原音轨内容和同步 |
| 短片自主创作 | 用同一份角色素材和明确主题制作约 12–20 秒 PV；提供固定的用户音频或明确无音频，避免不同试验自行换音乐 | 镜头作用、情绪推进、视觉焦点、文字可读性、跨镜头一致性，以及动态样片与最终输出的差异 |

时长仅为方便复验的样例，不成为运行时硬规则。包含至少一种与实际任务相关的制作难点；不要用单张图片平移通过测试后宣称覆盖了连续表演等能力。素材需可用于这次评测及预期发布范围，真实生图仍须按技能完成途径选择。

## 每个用例如何执行

1. 保存 brief、输入版本、skill 提交、模型/配置、环境及已有授权范围，完成四阶段实际制作。
2. 每次送审前保留自检记录和可播放证据；记录发现了什么、修正了什么、仍未验证什么。
3. 用最终渲染链路复核关键样片、全片预演和正式输出，并执行工程、视觉动态及用户三层验收。
4. 打包后在干净项目目录重渲染，记录命令、依赖、结果与差异；不能只验证原工作目录仍能运行。

没有用户音频的创作用例核查不存在 audio stream；复刻用例按实际输入核查全部原音轨。工程正确性与审美评价分别记录，不用平均分掩盖关键缺陷。

## 恢复和回改场景

在上述项目中执行，避免额外创造无关项目：

- **阶段 1 启动**：新项目中检查模型是否只追问必须由用户决定的事项、把答复记为批准依据，并在同一会话直接进入阶段 2 制作样片，不在阶段 1 停顿换窗口。
- **阶段续接**：阶段 2 完成后保留“待批准”状态，由用户在新会话发送真实续接消息。检查是否准确记录批准范围并直接制作阶段 3，以及质量目标、素材与未决缺陷是否恢复。
- **授权边界**：授权两个后端 profile 时，检查模型是否按素材在两者间择优并记录每张素材的来源，且不使用未授权途径；提议本地 AI 工具时，检查是否先说明用途、许可、体积和位置并等待同意。
- **中途恢复**：阶段未完成时换会话继续，检查是否保持未批准状态并处理未完成事项；不把恢复当成批准。
- **局部回改**：用户修改一个实际存在的角色特征或文字；检查相关镜头和依赖批准失效，无关已批准内容保持，旧证据仍可查。
- **证据或环境变化**：在评测副本中改动一个证据文件，或变更影响输出的字体/渲染设置；检查是否发现差异并仅复验受影响部分。

同一会话中的文字推演只记为走查，不记为跨会话验证。代理自检也不能替代真实用户批准。

## 结果与比较

每个结论关联产物路径/哈希、镜头与时间位置、实际检查方法及覆盖范围。记录缺陷、修正前后证据、未通过项和审阅人的判断，不把花费、镜头数量或素材分辨率当成质量分数。

比较 skill 修改前后时，固定 brief、输入、模型配置和生图途径，分别保存结果，并尽可能让审阅人在不知道版本的情况下比较。生成结果有波动，单次成功只证明该用例完成；重复验证之后再讨论稳定性。

评测记录应明确区分：脚本回归、工作流走查、真实跨会话运行、真实服务调用、完整 PV 审阅和重渲染。没有执行的项目保留待验证，不填入“通过”。
