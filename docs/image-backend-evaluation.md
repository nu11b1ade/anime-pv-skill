## 内置与中转对比

中转首轮7次请求、6次成功、7张图片；一次多参考提交状态unknown。精确尺寸提示词补测2次成功、3张图片。内置8次调用、8张图片；多参考、单图编辑使用相同输入素材。

- 二次元主视觉、中英文标题、参考换姿势、围巾改色和去字，两者均完成主要意图，单个样本没有显示后端明显画质劣势。
- 两者在要求1536×864时返回约1672×940/941，要求1024×1024时返回1254×1254；同时加提示词也没有兑现精确尺寸。
- 两者都输出真RGBA透明素材，alpha最大254，不应仅据此判失败。
- 局部编辑均未锁定非编辑像素。围巾编辑全图完全相同像素比例：中转4.20%、内置4.02%；这不是画质分数，也不能替代连续画面审查。
- 内置没有独立size/quality/n/mask参数；双图是两次调用，去字将mask作为参考图引导。并非底层参数完全一致的实验。
- 双参考内置首次成功，中转首次失败；后续修复验证见下节。

## Review核实与修复

两项P2均属实。官方wan2.6-image默认非混排模式要求1–4张参考图；同步混排需SSE，本适配器不支持。现补齐异步profile的纯文生图：generate默认enable_interleave=true、n=1、max_images=1，仅保存结果图片；显式不兼容参数在本地拒绝。max_images按上限验收，不错误要求恰好返回该数量。同步纯文本请求不再组装为无效付费请求，也不偷偷改用异步或其他模型。

诊断复现：旧GET ReadTimeout后恢复出现401，原setdefault会继续显示超时。现在first_diagnostic保留首次错误，diagnostic记录最新实际请求错误；本地拒绝恢复不覆盖原有字段。

23项离线测试通过，覆盖两项问题的回归；结构与链接检查、git diff --check通过。本轮未调用真实生图API，未push。官方依据见运行时配置文档。

文件核查：两份新增文档分别服务于用户选型和维护取证，应保留。实测原图和日志属于证据，不删除；本轮仅删除已完成修改任务的一次性tmp/update_backend.py，锁文件和缓存不批量清理，以免影响其他会话。

## 异步响应诊断复审修复

复审问题属实：FAILED和SUCCEEDED无图片分支未设置stage，被误判为本地拒绝恢复。现分别标记task-failed/task-canceled/task-status-unknown/missing-images，统一阶段poll-response。首次GET超时仍保留在first_diagnostic，最新响应错误更新diagnostic。不写入服务端原始错误文本。

新增回归不替换execute、_execute或request_json，仅在HTTP传输层模拟超时与响应：先触发三次GET超时，再恢复查询，覆盖失败、取消、未知状态和成功无图；修复前四个子场景失败，修复后24项测试通过。成功无图沿用pending以允许后续GET核查；终态失败拒绝恢复时不覆盖诊断，也不POST。本轮未调用真实API，未push。
